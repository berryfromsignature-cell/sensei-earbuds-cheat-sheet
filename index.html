<Requirements>

  • Hardware: Mac (Apple Silicon) + iPhone or Android + earbuds (mic + media).
  • AI stack: Claude Pro (with Claude Code) + ChatGPT Plus or Team.
  • Orchestration: Sensei (kosuke.ai) via MCP. Agents on Mac. Audio on phone.
  • Network: Tailscale (private tailnet between Mac and phone).
  • Optional: GitHub and Linear and Notion and Telegram for artifacts and alerts.

<Setup>

  • Join Mac and phone to the same Tailscale tailnet. Confirm both devices are online.
  • Connect Sensei as an MCP server in Claude Code and ChatGPT.
claude mcp add --transport http kosuke https://app.kosuke.ai/api/mcp
# ChatGPT: Settings → Developer mode → Add MCP → https://app.kosuke.ai/api/mcp
  • On the Mac run the Sensei event bridge (streams agent events to your phone):
npx @kosuke/sensei-bridge --events --tailscale --project viral-study
  • On the phone: install Sensei → enable Voice Mode → set earbuds as audio output.

<Workflow>

  • Define a high-level objective in Sensei (target and context and guardrails) by voice or app.
  • Sensei breaks it into a plan and routes work to Claude Code or Codex or ChatGPT on the Mac.
  • The Mac executes. The bridge sends structured events over Tailscale to Sensei.
  • Sensei converts high-signal events into short audio in your earbuds (not raw logs).
  • You control the run with Voice Mode and earbud gestures. No terminal UI required.

<Run signals>

INIT means Claude Code on your Mac just bound to Sensei over MCP. The repo is open and tools are checked. You get one short spoken line so you know the session is live. You never open Terminal for that.

PLAN is the full step list read once before any edits run. Example order: reproduce the bug then patch the file then run tests then open a PR. If the plan is wrong you say “stop” in Voice Mode and give a new objective. Sensei sends the updated plan to the agent on the Mac.

Order on the wire:

INIT → PLAN → (TOOL)* → CHECKPOINT* → BLOCK? → REVIEW? → OBJECTIVE → IDLE
TOOL is optional noise. Each line is one file edit or API call or shell command. Leave verbose mode off and you only hear CHECKPOINT and BLOCK instead of every tool.

CHECKPOINT is the main audio you live on. A real step finished. You hear what changed and which branch or folder or link holds the output and what the agent does next. That replaces watching a scrolling log.

BLOCK means the Mac stopped because only you can continue. Typical cases: merge or deploy needs approval or a secret is missing or policy blocked spend or data export. Answer with long-press voice. The agent resumes when Sensei gets your line.

REVIEW is the spoken safety check before anything hits production. You get scope and risk and a clear yes or no ask.

OBJECTIVE means the run succeeded. PR URL or report path or draft location plus any follow-up tasks the agent queued.

IDLE means nothing is executing but the bridge stays connected. Long-press to start again. Single-tap replays the last checkpoint without starting speech feed.

What Sensei speaks vs drops:

KEEP  PLAN · CHECKPOINT · BLOCK · REVIEW · OBJECTIVE
DROP  raw stderr · per-tool spam · stack traces

Example CHECKPOINT JSON (shortened for TTS):

{
  "type": "CHECKPOINT",
  "summary": "Tests green after auth.ts patch",
  "artifacts": ["branch fix/flake-auth"],
  "next": "open PR against main",
  "spoken": "Step three done. Tests passed. Next is pull request."
}

<Voice interface>

Everything you say in Voice Mode goes to the same pipe as typing in Claude Code. Sensei transcribes from your earbuds mic classifies the intent and injects a user message on the Mac. You steer runs while walking or driving without opening the laptop.

Control covers pause resume stop continue and rollback last checkpoint. Use it when the agent is moving too fast or you need to change direction mid-run.

Routing sends the next piece of work to Claude Code or ChatGPT or Codex on specific paths. Say which brain should own the next steps.

Context locks profile shards and docs. The viral-study profile plus brand.md plus batch 12 means every tool call stays inside your guardrails.

Actions are ship commands: open PR merge when CI is green deploy preview ping Telegram. You only hear audio again when a CHECKPOINT lands or a BLOCK needs you.

Introspection replays plan and state when you missed a line. Scheduling runs jobs on a clock and calls your earbuds when they finish or block.

Say any of these (Sensei maps to the Mac):

"pause the run"
"resume"
"stop and save where you are"
"switch to ChatGPT for the copy"
"use Claude Code on the repo"
"use viral-study profile and batch 12"
"open a PR with today's changes"
"merge if CI is green"
"what's the current state"
"why is it blocked"
"run this ingest every Monday at 6am"
"notify me when PR checks pass"

<Earbud controls>

Gestures are the fast path when you cannot talk. They hit Sensei on the phone which already has the live run over Tailscale. Configure once under Settings → Earbuds → Gestures.

Single tap is a silent status pull. Sensei reads the latest CHECKPOINT even if you muted TTS. You hear current step plus last change plus whether the agent waits on you.

Double tap toggles all Sensei speech in your ears. The Mac keeps working. Use this in meetings then double-tap again or single-tap once for a readout.

Triple tap is emergency stop for Claude Code. Tools halt on the Mac. Use when the agent is off track. Follow with long-press and a sharper objective.

Long press opens the mic. Your sentence becomes the next user message. That covers new tasks and BLOCK answers like approve merge or use branch hotfix only.

Hold + double cancels the run and clears the in-flight plan back to IDLE. Commits already on GitHub stay pushed. Check the repo if you are unsure what landed.

Gesture map:

1× tap      latest CHECKPOINT readout
2× tap      mute / unmute Sensei TTS
3× tap      interrupt Claude Code session
long press  Voice Mode → inject message
hold + 2×   cancel run → IDLE

After long press (examples):

"approve merge on PR 142"
"use branch hotfix/auth only"
"stop and run tests only"

<Guardrails>

Persistent project profile in Sensei. Same repo and stack and limits every run.

Create profile:

/profile new --name viral-study --repo <url> --stack claude,chatgpt

System instructions:

"You are my autonomous research operator. Objective: analyze short-form video at scale (4,812,506 TikToks) and surface what drives virality. Constraints: never merge without approval. Never make payments without approval. Never exfiltrate raw creator data. Request approval for high-risk steps. Process: plan and shard workloads and write features and summaries. Outputs: concise Checkpoints and diffs and links and next actions for audio. Not stack traces."

Attach reference docs:

/profile attach --docs brand.md playbook.md study.md

Policy layer:

/policy set --deploy=confirm --cost>$0=confirm --pr=auto --data=readonly

<Operating loop>

  • Start a run with one clear objective or a saved Sensei template.
  • Listen for PLAN and CHECKPOINT and BLOCK and OBJECTIVE on your earbuds.
  • Approve or redirect or stop with voice or earbud gestures.
  • Close with a results summary and the next recommended batch or task.
  • Iterate weekly. Update profile and guardrails and attached docs when the playbook changes.
